# Переустановка ОС по сети

Ситуация: провайдер выдал не Ubuntu, а панель управления переустановку либо не
поддерживает, либо молча игнорирует. Чинится сетевой переустановкой прямо с
живой системы — панель не нужна.

## Сначала убедись, что переустановки действительно не было

Свежий `uptime` ещё ничего не значит — сервер мог просто перезагрузиться.
Смотри на даты:

```bash
ls -l --time-style=long-iso /etc/machine-id /etc/ssh/ssh_host_ed25519_key
```

Если они старые — диск не трогали. При реальной переустановке `machine-id` и
ключи хоста генерируются заново.

## Снять параметры до начала

```bash
ip -4 addr show scope global; ip -4 route show     # адрес, маска, шлюз
ip -6 addr show scope global
[ -d /sys/firmware/efi ] && echo EFI || echo BIOS
lsblk                                              # какой диск основной
cat /root/.ssh/authorized_keys                     # ключ доступа
```

Особое внимание на нестандартную адресацию — маска `/32` со шлюзом вне подсети
встречается часто и ломает наивные установщики.

## Запуск

```bash
curl -fsSL -o /root/reinstall.sh \
  https://raw.githubusercontent.com/bin456789/reinstall/main/reinstall.sh

bash /root/reinstall.sh ubuntu 24.04 \
  --username root \
  --ssh-key "$(cat ~/.ssh/authorized_keys)"
```

Скрипт правит GRUB и **не перезагружает сервер сам**. Перед ребутом сверь блок
`NETWORK INFO` в выводе — там должны быть реальные адрес, маска и шлюз. Если
что-то не так, отмена без последствий: `sh reinstall.sh reset`.

Когда всё верно:

```bash
reboot
```

Дальше 10–20 минут вслепую: машина грузится в Alpine по сети, тянет облачный
образ Ubuntu и разворачивает его на диск.

## Грабли

**`--username root` обязателен.** Без него скрипт интерактивно спрашивает имя
пользователя и по SSH без TTY падает с `Line NNNN return 1`.

**Пароль и ключ одновременно задать нельзя** — `Cannot set both password and ssh
key`. Бери ключ, пароль поставишь после первой загрузки через `chpasswd`.

**Нужен запасной доступ.** Если сеть не поднимется, из SSH машину не вернуть —
только VNC или rescue-режим в панели провайдера.

**Мёртвый хост врёт про доступность.** Пока сервер лежит, оборудование
провайдера продолжает отвечать SYN-ACK, и `nc -z` показывает «порт открыт» на
22 и 80. Проверять надо SSH-баннер:

```bash
(printf '\n'; sleep 3) | nc -G 4 <IP> 22 | head -1
# живой хост → SSH-2.0-OpenSSH_9.6p1 Ubuntu-...
# мёртвый    → пусто
```

**Host key сменится.** После переустановки почисти запись, иначе получишь
`Host key verification failed`:

```bash
ssh-keygen -R <IP>
```

## Ожидание в цикле

```bash
until (printf '\n'; sleep 3) | nc -G 4 <IP> 22 2>/dev/null | grep -qi ubuntu; do
  echo "$(date +%H:%M:%S) ещё не поднялся"
  sleep 60
done
echo "Ubuntu поднялся"
```

На время установки на порту 80 работает веб-просмотр логов — туда можно
заглянуть, если процесс затягивается.
